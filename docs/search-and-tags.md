# 搜索和文章标签

## 搜索范围

点击导航栏放大镜打开搜索。支持标题、全文、作者、标签和期数；多个空格分隔的关键词需要同时匹配。标题匹配优先，其次是作者及分类信息，最后是正文。相同得分按日期倒序排列。

标签和期数下拉框可以与关键词组合，也可以单独筛选。最多展示 30 项结果，结果较多时可增加关键词。搜索索引读取失败时可以重试。

搜索使用 Hugo 生成的静态 `index.json`，无需额外后端或账号。目前索引包含已发布的文章和相册；新增文章或修改标签后，需要重新构建并发布 GitHub Pages。

## 标签由谁确定

作者提出、编辑确认，并在文章 Markdown 文件开头的 Front Matter 中填写。程序只读取这些标签，不自动根据正文给文章贴标签。

在现有 YAML 头部增加或修改 `tags`，不要在正文末尾添加另一个配置块。例如：

```yaml
---
title: "文章标题"
author: "作者昵称"
date: '2026-10-01T12:00:00+08:00'
draft: false
categories: ["Oct.2026"]
tags: ["校园生活", "随笔"]
---
```

此项目的 `categories` 目前用于期数；`tags` 用于主题或体裁。已有标签会自动进入标签页面和搜索筛选框，无需在 Hugo 配置中逐个注册。

建议每篇选 2–4 个能帮助寻找相关文章的标签。先复用已有名称，例如统一使用“校园生活”，避免同时出现“校园”“校园生活”“学校生活”等含义接近的名称。标签数量只是编辑建议，代码没有强制限制。

没有填写标签的文章仍可通过标题、正文、作者及期数搜索。未填写标签时，下拉框不会凭空生成主题选项。当前已发布文章还没有形成主题标签集合；本次修改没有擅自改动文章内容或补标签。

## 文件位置

- `themes/blank-magazine/layouts/_default/index.json`：生成完整搜索索引。
- `themes/blank-magazine/layouts/partials/header.html`：搜索入口和筛选控件。
- `assets/js/search-engine.js`：匹配、筛选和排序。
- `assets/js/search.js`：读取索引和显示结果，用户文字使用纯文本输出。
- `assets/css/search.css`：搜索弹层及窄屏排版。

GitHub Pages 项目子路径通过 Hugo 的 `relURL` 和文章的相对链接处理；无需把接口地址写死为 `/index.json`。
