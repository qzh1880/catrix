# 评论点赞 反馈 推荐与游戏排名

本次在既有评论、回复、举报功能上增加社区互动，并将俄罗斯方块改为独立游戏页面。前端仍由 Hugo 构建并部署到 GitHub Pages，动态功能复用现有 Cloudflare Worker 和 D1。

## 修改内容

### 评论点赞

公开的顶层评论和回复都可以点赞、取消。按匿名浏览器标识去重，同一标识对同一留言最多计一票；刷新后可恢复点赞状态。服务端拒绝对已删除或未公开评论点赞。

### 网站反馈

新增 `/feedback/`，导航“更多”中增加“网站反馈”。用户填写昵称和建议即可发布，无需账号。建议按点赞数倒序排列，同票按新到旧排列，每页 20 条。点赞后回到第一页重新排序，让支持最多的建议位于顶部。

页面底部“管理员处理反馈”使用现有 `COMMENTS_ADMIN_KEY`。验证凭证后可删除建议；删除清空昵称和正文，保留请求标识以防网络重试重新发布。退出或刷新页面后凭证不会保留。

反馈内容采用纯文本展示，昵称最多 40 字符，正文 2–2000 字符。提交失败保留输入；重试相同内容不会生成重复建议。

### 相关文章推荐

文章底部默认显示最多三篇推荐，并排除当前文章。排序依据：每个相同标签加 10 分、相同作者加 3 分、相同期数加 1 分，同分按文章日期从新到旧排列。没有相关元数据时，使用其他最近文章补足。

卡片显示“相同标签”“同一作者”“同一期内容”或“继续阅读”，说明推荐依据。主题由编辑填写的 `tags` 表达，不使用模型猜测正文主题。当前已同步的文章标签可以直接参与推荐。

新推荐组件使用 `recommendations: false` 作为单篇关闭开关，替换原先由 `showRelated` 控制的推荐模块；因此原文章的 `showRelated: false` 不再关闭新组件。需要关闭时请明确改用新开关。

### 独立俄罗斯方块页面

`/games/` 仅显示游戏入口卡片，移除直接嵌入的俄罗斯方块棋盘。点击卡片进入 `/games/tetris/`，保留返回游乐场链接和原有合成大学校入口。

- 休闲模式：轻松、标准、挑战三档，分别使用标准下落间隔的 1.6、1、0.6 倍，不提供赛后入榜表单。
- 排位模式：统一标准难度，每局最多 15 分钟有效游戏时间；达到 12000 次操作上限也会结算。暂停时间不计入有效游戏时间。
- 游戏进行或暂停时不能切换模式、难度；重新开始一局时才读取选择。
- 排位结束后自愿填写 1–24 字符昵称参与排名，也可直接开始下一局。休闲局不能转为排位局。
- 每局排位会话从创建起两小时内可提交；重复提交同一局只保留一份成绩。

榜单采用北京时间。周榜从周一 00:00 开始，月榜从每月 1 日 00:00 开始，总榜包含全部已保存成绩。按成绩提交时间归属周期；每个浏览器标识在各榜展示其最高成绩，分数相同时先提交的在前，展示前 50 名。

本机最高分仍用于个人参考，可以包含不同休闲难度的成绩，不参与线上榜单比较。

## 成绩校验和匿名身份的边界

排位开始时由服务端签发随机会话 ID 和方块种子。浏览器按固定 50ms 步长计时，记录移动、旋转、暂存、下落及计时记录。服务端使用相同引擎和种子重放，计算分数及消行数，不使用请求中自报的分数。

服务端验证对局归属、有效期、版本、游戏结束状态、操作数量和记录时间；请求体上限 300KB。成绩表以会话 ID 为唯一键，避免重试重复入榜。

这是休闲社区排行榜，不是具有实名身份和强反作弊能力的赛事系统。重放可以拒绝无效操作和直接篡改分数，但不能证明操作由真人完成，也不能阻止机器人生成符合规则的操作。规则变更必须提升 `rules.js` 中的版本，并规划旧榜单兼容方式。

匿名标识存于浏览器 localStorage。服务端只保存其加盐摘要；同名不是同一人，更换浏览器、清理存储或主动生成新标识都可能成为新的记录。因此点赞数不等于独立人数，排行榜也不提供跨设备账号合并。旋转 `COMMENTS_RATE_SALT` 会改变匿名摘要，请将其作为身份关联变更处理。

基础频率限制按 IP 每 10 分钟分别计算：点赞操作最多 100 次、反馈提交最多 10 次、排位开局最多 20 次、成绩提交最多 10 次。校园共享出口可能共用配额。现有评论和举报配额保持各自独立。数据库不保存原始 IP。

## 数据库与上线步骤

新增迁移 `worker/migrations/0003_community_rankings.sql`，创建点赞、反馈、排位会话和成绩表，不修改已有评论正文。部署前应确认前两次迁移已应用。

在仓库根目录由维护者执行，使用当前实际部署配置：

```powershell
npx.cmd wrangler d1 migrations apply catrix-comments --remote --config wrangler.comments.toml
npx.cmd wrangler deploy --config wrangler.comments.toml
```

先在测试环境核验，尤其检查较长对局重放的 Worker CPU 用量是否适合当前配置，再发布正式环境。若数据库或 Worker 已更名，应先修改配置并使用实际名称。

本次在 `worker/comments-worker.js` 增加 `/community/` 路由。若站长只给自定义域名配置了 `/comments*` 路由，必须让同一 Worker 同时接收 `/community/*`；通过完整自定义域名绑定访问时需确认新路径能到达同一服务。

沿用 `DB`、`COMMENTS_ADMIN_KEY`、`COMMENTS_RATE_SALT` 和 `COMMENTS_ALLOWED_ORIGINS`，无需新增 Secret。不要把密钥写入仓库。

Worker 发布并验证后，再发布 GitHub Pages。动态接口域名仍读取 `hugo.toml` 中的 `params.comments.apiURL`，去掉末尾 `/comments` 后拼接 `/community/…`。游戏通过 Hugo 生成的 `/community-config/index.json` 获取相同地址；该文件只包含公开接口地址。

`params.comments.enabled` 仅控制文章评论区展示，不会关闭反馈、排行榜或后台接口。若要停用动态服务，需分别移除入口或关闭 Worker 对应路由。

已提交反馈、点赞、排位成绩保存在 D1 中。未提交且过期的排位会话会在后续开局时清理；已提交会话、成绩及点赞记录持续保留，后续可按站点的数据保留政策清理。删除评论或反馈不会自动清理与其关联的点赞摘要。旧游戏总榜尚不存在，本次不会导入本机历史最高分。

## 验证与本地预览

```powershell
node --test worker/tests/*.test.mjs static/games/tetris/tests/*.test.mjs
hugo
node scripts/preview-comments.mjs
```

需要 Node.js 24 和 Hugo。若 Hugo 不在 PATH，设置 `HUGO_BINARY` 为其实际路径；可通过 `COMMENTS_PREVIEW_PORT` 更换端口。

预览使用内存数据库，会自动执行全部 SQL 迁移，并提供标明“演示”的评论及反馈。重新启动后，本地评论、点赞、反馈和排名都会清空，不连接正式 D1。本次预览端口为 1315。

验收清单：

1. 给评论点赞、刷新确认，再取消点赞。
2. 发布反馈、点赞，确认高票在前；用管理凭证验证管理入口。
3. 打开文章，确认推荐不包含自身，卡片依据与文章标签、作者对应。
4. 从小游戏列表进入独立游戏页，休闲模式选择难度并开始，结束后不出现排名报名表单。
5. 排位模式完成一局，填昵称提交，核验后的分数与页面分数一致；切换周榜、月榜、总榜。
6. 刷新榜单确认成绩仍存在；通过网络失败重试提交时不重复入榜。
7. 在手机宽度检查表单、游戏按钮、榜单和推荐卡片是否溢出。

## 主要文件

- `worker/community.js`：点赞、反馈、排行榜接口及管理鉴权。
- `worker/rankings.js`：成绩重放与榜单周期计算。
- `static/games/tetris/rules.js`：两端共用的随机数和排位限制。
- `static/js/community-client.js`：浏览器匿名标识、请求和点赞按钮。
- `content/feedback.md` 与 `layouts/_default/feedback.html`：反馈页面。
- `layouts/partials/recommendations.html`：静态文章推荐。
- `static/games/tetris/game.js`：模式切换、操作记录、赛后报名和榜单。

本次同时修正预览脚本和测试对已移除 `worker/worker.js` 的引用，统一使用实际部署入口 `worker/comments-worker.js`。
